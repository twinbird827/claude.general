# Adjudication（finding-verifier の票勘定）

finding-verifier の票をどう数え、何票で決めるかの正本。読み手は code-review-plan-loop / plan-refinement-loop の2スキルで、裁定に入る前に Read する。**どの指摘を検証へ回すか・最初の起動に何件渡すかは各スキルの領分**であり、ここには書かない。却下してよい理由そのものは `finding-criteria.md` の クラス 節。finding-verifier 自身はこの文書を読まない — 票の重みを知らないことが独立性の条件。

## 票の値

- **CONFIRMED** / **REFUTED** — 決定票。
- **UNVERIFIABLE** — 棄権。決定票として数えない。

## 決着の規則

- **1人目が CONFIRMED なら、そこで確定**（指摘を生かす方向に追加検証は要らない）。以下は REFUTED か UNVERIFIABLE が1票でも出たときに掛かる。
- **決定票が2票そろうまで決着しない**（2-decisive-vote floor）。この下限は両方向に等しく掛かる — 落とすのも生かすのも同じ2票。
- 決定票が2票以上そろったら**決定票の多数決**で決める。REFUTED 多数 → その指摘を落とし、サイドカーの `rejected` へ反証つきで記録する。CONFIRMED 多数 → その指摘を生かす。
- REFUTED か UNVERIFIABLE が出たら、追加の前にその問いが**事実の問いか価値の問いか**を判定する（`finding-criteria.md` の クラス 節 の「事実の問題は上げない」ゲートが正本）。価値の問いは票で決めない — そのままサイドカーの `open_needs_user` へ。
- **決着しなかった事実**（検証者の追加 が打ち切られてなお決定票が2票未満、または同数）→ サイドカーの `open_needs_user` へ（`reason: 追加検証でも決着しなかった事実`）。同数はそれ自体では終端でなく、次節の当て直しの対象 — ここへ来るのは上限の3人に達したとき、または 根拠 が構造的に空で1票で打ち切ったときだけ。
- 多数決で出た結論は、**新たな REFUTED として次の検証ラウンドを起動しない**。ここで止める。

## 検証者の追加

この節は 決着の規則 の1つ目のバレット（1人目が CONFIRMED）で確定しなかったときに掛かる。追加する人数は、追加後に**多数決が付きうる**最小数（決定票2票の下限は 決着の規則 のとおり残る）。数えるのはそれまでに走った検証者の票すべてで、票が増えるたびにこの規則を当て直す（棄権は決定票に数えないので、UNVERIFIABLE だけなら2人）。ただし 根拠 が構造的に空の指摘（受け手が「差分のみ・追加検証なし」と明示して回してきたもの）は、決着の規則 の 事実か価値か の判定を当てたうえで事実として残ったものだけがここへ来る。そのとき1票目に UNVERIFIABLE が出ても検証者は追加しない — 同じ空の 根拠 を渡すだけなので票は動かず、1票で打ち切って 決着の規則 の「決着しなかった事実」として `open_needs_user` へ送る（`reason` は既存値 `追加検証でも決着しなかった事実` を流用し、値を増やさない）。

追加した検証者に渡すのは**その指摘1件だけ**（クラスタ単位で回さない）。**1件あたりの検証者は最大3人** — 3人ぶんの票が出てなお決定票2票の多数決が付かないなら、そこで打ち切って 決着の規則 の「決着しなかった事実」として `open_needs_user` へ送る。
