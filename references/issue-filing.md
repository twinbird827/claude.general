# tracker への起票

## 別課題（スコープ外指摘）の起票

次の2種は、プラン本文に持ち込まない。承認ゲートは無い。

- 対象のプラン／差分とは**別の変更**に属する指摘（既存不具合・同種の別箇所・後続リファクタ）。起票のタイミング:
  - 既定: CONFIRMED 判定の直後にその場で起票する。
  - cr-loop で変更セットを設計するラウンド: 同種の別箇所は変更セットの設計（同型横展開を含む）を終えるまで起票を保留し、**同型横展開 スイープが拾った同型箇所は起票しない** — 変更項目へ取り込む側が優先する（差分外でも一括適用するのがそのスイープの目的で、起票へ回すと同一クラスの欠陥がラウンドをまたいで逐次発見される）。
- **差分レビュー起案（code-review-plan-loop）に限り**、変更セットが意図的に外した確認済み指摘（差分のテーマ外にある、振る舞いを変えない品質改善など）。スコープ外と決まった直後に起票する。プラン精査（plan-refinement-loop）にこの種別は無い — 事実として妥当な指摘を落とす出口を作らないため。

いずれも**レビューが挙げた確認済み指摘**が対象。起案者自身が意図して省いた設計判断は指摘ではなく、doctrine 姿勢 節 のとおりプラン本文に1行だけ残す。

- **裁定は必須。重大度は問わない。** 起票は公開・不可逆なので finding-verifier の CONFIRMED を必ず経由する。Minor/Nit であっても「別課題として起票する」指摘だけは裁定をスキップしない。
- **重複確認を先に。** tracker（「issue 検索」）とサイドカー（cr-loop では前ラウンドから carry したもの）の `filed_issues` を検索。ヒットしたら起票しない。
- **コマンドは hosting の表から引く**: hosting は `~/.claude/references/mr-workflow.md` の 規則 節で決め、`~/.claude/references/git-hosting/<hosting>.md` の「issue 検索」「issue 作成」「issue へ追記」の行を使う。既存 issue へは追記し、本文を置換するコマンドは使わない。
- **本文**: タイトル＋数行（何が / どこ `file:line` / なぜ問題か / このプラン・PR へのリンク）。repo 内の gitignore 済み `.tmp/` に置いて渡す（本文を argv に直書きしない）。粗くてよい — その issue は後で自身のレビュー回を持つので、ここでの文言精度は無駄。起票（追記）が成功したらそのファイルを消す。
- **記録**: `#<N>` をサイドカーの `filed_issues` へ。**issue 本文はプランに書かない。**
